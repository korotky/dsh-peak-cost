# Разработка

Короткая шпаргалка: как поднять, как итерировать, что здесь ломается не так, как ожидаешь.

## Окружение, на котором всё проверялось

|      |                                                           |
| ---- | --------------------------------------------------------- |
| dsh  | `0.2.1-rc.5` (npm-тег `latest`), профиль `web`            |
| Node | 24 локально, CI гоняет 22 и 24                            |
| ОС   | Linux/WSL2; браузер для проверки — headless Chrome по CDP |

Другие версии dsh не проверялись. Внутренние API хоста меняются от релиз-кандидата к
релиз-кандидату — при обновлении dsh сначала прогоняйте `npm test` и открывайте поповер
глазами: диагностика в нём покажет, что перестало находиться.

## Установка для разработки

```sh
dsh plugin --profile web add /абсолютный/путь/к/этому/репозиторию
```

pnpm ставит локальный каталог **ссылкой** (`link:`), поэтому правки в репозитории сразу видны
хосту — но с оговоркой про горячую замену ниже.

## Горячая замена не работает при установке ссылкой

Проверено и записано в [ADR 0005](adr/0005-hot-reload-only-for-copied-install.md): HMR
канонизирует путь события через `realpathSync` (получается путь репозитория), а кэш
ES-модулей держит URL через симлинк профиля. Совпадения нет — модуль не заменяется.

Рабочий цикл: изменить файлы → пересобрать композицию → обновить страницу.

```sh
node scripts/dev-reload.mjs      # находит строку плагина в Plugins, выключает-включает, обновляет страницу
```

Скрипту нужен Chrome с отладочным портом (см. ниже). Без него — вручную: Plugins →
переключатель строки плагина → выключить и включить → обновить страницу.

## Проверка глазами через CDP

```sh
google-chrome --headless=new --remote-debugging-port=9222 \
  --user-data-dir=/tmp/dsh-cdp --disable-gpu "http://127.0.0.1:3080/?token=..."
```

Токен печатает `dsh web` при старте. Дальше:

```sh
node scripts/cdp.mjs url                  # адрес открытой страницы
node scripts/cdp.mjs eval "document.title"
node scripts/cdp.mjs shot shot.png        # скриншот в файл
node scripts/cdp.mjs click "Peak Cost"    # клик по элементу с таким текстом
node scripts/cdp.mjs clickAt 69 138       # клик по координатам
node scripts/cdp.mjs reload               # перезагрузка без кэша
```

Порт и адрес можно переопределить переменными `CDP_PORT` и `CDP_HOST`.

## Что нужно в профиле, кроме самого пакета

Эти записи живут в `~/.dsh/profiles/web/cordis.patch.yml` и без них плагин работает не полностью:

```yaml
# источник индекса для Discover (не обязателен для самого плагина)
- id: plugin-market
  config:
    indexes:
      - https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json

# адресуемая строка: без неё сервис настроек не создаёт namespace,
# и форма настроек на странице Plugins не появляется
- id: peak-cost
  name: dsh-peak-cost

# наблюдение за исходниками (при установке ссылкой не спасает, см. ADR 0005)
- id: hmr
  disabled: false
  config:
    root:
      - /абсолютный/путь/к/репозиторию
```

## Маршрут состояния

`GET /api/dsh-peak-cost/state?session=<id>&ledger=1` — фаза, стоимость сессии, леджер,
настройки, диагностика. `POST` с JSON-патчем пишет настройки через `settings.update`.
Маршрут наследует проверку доверия хоста (`connection.requestRejection`).

## Сборка

```sh
npm run build     # dist/dsh-peak-cost-<version>.tgz + sha256, с проверкой состава пакета
```

Сборка не компилирует код: хост грузит `client.js` как есть. Задача сборки — не выпустить
пакет без `lib/`, без `cordis.patch.yml` или с тестами внутри.

## Проверки перед PR

```sh
npm run typecheck && npm run format:check && npm test && npm run build
```
