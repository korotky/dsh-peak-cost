# Горячая замена хост-модулей работает только для скопированной установки

При установке плагина ссылкой (`link:`) правка файлов в workspace не применяется: HMR канонизирует путь события через `realpathSync` (получается путь workspace), а кэш ES-модулей держит URL через симлинк профиля (`file:///home/lega/.dsh/profiles/web/node_modules/dsh-peak-cost/...`). `esmHas(url)` не находит совпадения, `Include` тоже, остаётся событие `hmr/change`, которое никто не слушает. Проверено диагностикой самого сервиса: конфиг наблюдения корректен (`root` с нашим каталогом), watcher поднят, chokidar события отдаёт — дело именно в расхождении путей.

Отвергнуто: наблюдение за путём профиля (chokidar отдаёт `node_modules/dsh-peak-cost/...`, но канонизация всё равно уводит в workspace) и правка самого HMR (чужой код в поставке). Рабочий обход — переключение бандла, оно запускает пересборку композиции, и та заменяет модули по факту изменённых файлов; это автоматизировано скриптом `.scratch/reload-plugin.mjs` (CDP: найти переключатель строки, выключить-включить, обновить страницу). Настоящая горячая замена заработает, если пакет установлен копией (tarball или реестр): тогда ключ кэша совпадает с каноническим путём, и событие файла попадает в `esmHas`.
