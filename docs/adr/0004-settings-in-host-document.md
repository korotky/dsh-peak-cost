# Настройки: namespace хоста плюс собственный вклад на страницу Plugins

Настройки объявлены `Config` с пятью volatile-полями. Хранилище — `settings.update('peak-cost')`, то есть запись профиля в `cordis.patch.yml`. Форма на странице Plugins рисуется не хостом автоматически: `plugins.row.config` и `plugins.bundle.config` — keyed-слоты, и вклад в них даёт сам плагин по ключу своей записи (`peak-cost`) и пакета (`dsh-peak-cost`). Поэтому форма появляется только у бандла, чья клиентская половина эти ключи зарегистрировала.

Три причины, из-за которых это заработало не сразу, и все три неочевидны: форма хоста показывает только volatile-поля; `schemastery` не резолвится из каталога плагина, установленного ссылкой (`import` ищет `node_modules` вверх по workspace, а `DSH_PROFILE_DIR` есть только в окружении shell-команд, не самого хоста) — резолв идёт перебором якорей, сейчас это `profile:web`; и у строки должна быть адресуемая запись `- id: peak-cost` в патче профиля, иначе у сервиса настроек нет namespace.

Отвергнуто: `localStorage`, файл настроек плагина, и расчёт на автоматическую форму хоста. Следствия: панель в поповере и форма на странице Plugins пишут в один namespace, поэтому не расходятся; при отказе `settings.update` плагин сообщает об этом в диагностике и не подменяет запись файлом. Ограничение, которое стоит помнить: ключи слотов и id записи — часть контракта, при переименовании плагина или записи форму нужно перенастроить.
